## Fix: uuid in repo backfill INSERT (Important finding)

### Finding
The `train_model_repos` table inherits `ModelMixin` whose `uuid` column is `String(64)`, `nullable=False`, `unique=True` (`app/core/base_model.py:78-85`). The original migration's `INSERT INTO train_model_repos (name, framework, status, ...)` omitted `uuid` → would fail at runtime on the live PG DB (plan Step 5).

### Fix applied
- Added `import uuid` at module top (local stdlib, keeps migration lightweight — no app-code import).
- INSERT now includes `uuid` column: `INSERT INTO train_model_repos (uuid, name, framework, status, created_time, updated_time) VALUES (:uuid, :name, :framework, 'draft', NOW(), NOW()) RETURNING id`, with `{"uuid": str(uuid.uuid4()), ...}` (hyphenated uuid4, ≤64 chars, satisfies the unique NOT NULL column).
- Verified the backfill `UPDATE train_models SET repo_id = :rid, version = :ver WHERE id = :id` stays as-is — it cannot violate the partial unique index `uq_train_models_name_version` (`CAST(is_deleted AS INTEGER) = 0`) because live data has 41 active rows, 0 deleted rows, 0 name-version collisions. No code change needed.
