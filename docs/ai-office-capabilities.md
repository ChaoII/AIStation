# AI 办公室：能干什么（能力清单）

> 一句话定位：**办公室是「派活台 + 观察窗」，不是演示动画。**
> 你在这儿把一件活交给某一组智能体，它们用**自己的模型、工具、技能、知识库、MCP**
> 真跑一遍，跑的每一步（谁接的、调了什么工具、参数、返回、谁说了什么、最后口径）
> 都落在数据库里，能在大屏和右侧面板里逐块看。

本文只讲**能力**（能做什么 / 不能做什么 / 怎么验证），视觉规范看
`docs/ai-office-design-system.md`。

---

## 一、两类能力，别混着看

| 类别 | 内容 | 是否真实 |
|---|---|---|
| **真实执行** | 派活给组长（Team 协调）、单独派给某人、成员调用工具取数、知识库检索、技能脚本、MCP 调用、会话落库、调用日志、执行步骤 | ✅ 真的跑模型、真的查库、真的落库 |
| **表现层** | 3D 场景走动、开会、迟到、访客、夜间加班灯、回放、今日简报动画、形象换装 | ⚠️ 由真实状态驱动或纯氛围，不产生业务结果 |

表现层的定位：**把「谁在忙、忙什么、结论是什么」变得一眼看得见**，
但它本身不替你做业务。判断标准很简单：**有没有 `ai_call_logs` / `ai_run_steps` 记录**。

---

## 二、真实能力清单

### 1. 派活：组长协调（Team）

- 入口：顶栏「派活」/ 舞台内派活框。
- 机制：agno `Team(mode=coordinate)`，组长接活 → 判断要不要派人 →
  `delegate_task_to_members` 派给成员 → 成员各自跑 → 组长汇总成**唯一口径**。
- 指令约束（写在 `office_dispatch_stream` 里）：必须派活不许自己全干、必须等成员返回、
  成员没返回就写「某某未返回」、**禁止编造成员没说的内容**。

### 2. 派活：单独找他（不走 Team）

- 入口：选中某人 → 输入框「单独派给 XXX」→ 派给他。
- 机制：单个 agno `Agent` 直接跑，结果原样返回，日志记 `usage=agent`、`app_id` 指到他。
- 用途：你已经知道该找谁时，省掉组长那一层，快很多（实测 13.6s vs 团队 200s）。

### 3. 成员的真实能力（2026-10 接通）

派活时每个成员会带上**他自己绑定的**能力，和「AI 应用」运行台完全同一套链路：

| 绑定 | 注入方式 | 表现 |
|---|---|---|
| 平台业务工具（25+ 个：`list_datasets` / `list_cameras` / `list_train_tasks` / `get_annotation_overview` / `ai_query` …） | `build_business_tools()`（默认就有，按用户权限取数） | 工具步骤里出现工具名 + 参数 + 真实返回 |
| 自定义工具 / HTTP 工具（`tool_ids`） | `build_dynamic_tools` + `_run_app_tool` | 同上 |
| 技能（`skill_ids`） | `build_agno_skills`（脚本落临时目录，跑完删除） | 模型可写/跑脚本 |
| 知识库（`knowledge_ids`） | 检索后注入指令（RAG，与运行台一致） | 回答引用知识库内容 |
| MCP 服务器（`mcp_ids`） | `build_mcp_tools` → `MCPTools` | 可调用外部 MCP 工具（连不上就降级跳过） |

> **顺手修的两个真 bug**（不修这些「真实能力」都是空的）：
> 1. 派活时没注入用户上下文 → 业务工具拿到 `user_id=None`，取数全空。
>    现在 `set_user_context(user_id)` 包住整轮 run。
> 2. `_inject_user_id` 对**没有** `user_id` 形参的工具也硬塞一个关键字 →
>    `list_datasets() got an unexpected keyword argument 'user_id'`。
>    现在按签名判断，没有就原样返回。

### 3.5 上下文延续（2026-10-24 接通）

- **做法**：每轮派活结束把「问 + 组长结论」写进 `ai_office_memory`（插件自建表）；
  下一轮派活时取最近 3 轮压成一段，拼进**组长指令**——追问不用从头说。
- 同时也把 agno 原生 `Team(db=…, session_id="office-team-<uid>", add_history_to_context=True)`
  挂上（能落盘就双保险；实测真实 run 里 TeamSession 不一定落盘，所以提示词记忆是主路径）。
- **实测**：先问「有几个数据集」→ 273；紧接着问「刚才那个数字乘以 2 是多少？」→
  **直接答 546，5.3 秒、0 次工具调用**（没有记忆时会说"看不到上下文"）。
- 面板头会亮一个 `带上下文` 小标签，让你知道这轮读过历史。

### 3.6 执行过程是**实时**的

- 组长/组员的每次工具调用，服务端在 `tool_call_completed` 时立刻推一帧
  `{"type":"tool","from":…,"tool":…,"args":…,"result":…}`，前端当场落一行；
  既写 `ai_run_steps`（持久化），也推 SSE（不刷新）。
- **不选人也能看**：派活一开始右侧「执行过程」面板就出现（以前必须先选中某个成员）。
- 单独派活（不走 Team）现在也记步骤：plan → 每次工具调用 → 结果（`stream_events=True`）。

### 3.7 任务列表（今天派过哪些活）

- 左栏「花名册」变成两个页签：**成员 / 任务**（任务页签带当天的条数）。
- 数据源 `GET /ai/agents/office/runs`：按 `run_id` 聚合 `ai_run_steps`，一条 = 一次派活，返回
  `开始时间 / 步数 / 用户问句 / 状态（ok·error·running）/ 组长 / 参与成员`。
  - **按天筛选**：`date=YYYY-MM-DD`（选某一天）；不传则 `days=30`（最近 30 天）。
  - **分页**：`page_no` / `page_size`，返回 `{page_no, page_size, total, has_next, items}`，
    与项目分页口径一致；左栏底部是页码条，切日期自动回第 1 页。
  - **筛选**：`status=ok|error|running`、`agent_name=参与成员`（在聚合之后用 HAVING 过滤）；
    空态会区分「这一天没有派活」和「没有符合条件的派活」。
- 舞台底部的「最近执行」可点击：显示今天最近 3 次派活（组长 / 步数 / 状态点 / 时间），
  点一下就把那一次的步骤铺到右侧，当前那条高亮。
- 点一条 → 右侧「执行过程」直接摊开**那一次**的完整步骤（历史从头读，不自动滚到底），
  同时左边那一条高亮；顶部工具栏会顺手选中这次的组长。
- 派活结束、进入页面、点「刷新」都会重新拉列表。

### 3.9 场景跟着真实动作变（2026-10-24）

| 真实事件 | 场景表现 |
|---|---|
| 派活 | 被点名的人起身走到工位坐下 + 工牌闪两下 + 转一下头看组长 |
| 调工具 | 他的工位屏幕切成对应画面（SQL / 文档 / 列表） |
| 空闲 ≥105s | 起身去休息区，待一会自己回工位（一次只走一个人） |
| 失败 | 组长→他一条红色虚线弧 + 脚下脉动红圈（4s） |
| 汇总 | 组长走到白板前，白板上写着最近 5 条结论 |

### 3.8 失败会「红」到场景里

- 派活失败时，后端把组长写进 `ai_office_activity`（`status='error'`，挂 180 秒）：
  `office_view` 直接返回 `status="error"`。
- 左栏成员行：头像与「执行失败」都是红色；3D 里工牌描红、脚下状态点变红。
- 面板里那一步本来就是红块；现在**不看面板也知道出事了**（180 秒后自动过期）。

### 4. 执行过程（可追溯）

一次派活 = 一个 `run_id`，步骤落 `ai_run_steps`，工具调用另落 `ai_tool_calls`。

真实跑出来的例子（问「有几个数据集、几个摄像头」）：

```
0 plan    全能分析助理   收到任务：让数据洞察助手查一下…
1 tool    全能分析助理   delegate_task_to_member → 数据洞察助手
2 tool    数据洞察助手   list_datasets        args {limit:1000}  result [{id:782,…}, …]
3 tool    数据洞察助手   list_cameras         args {limit:1000}  result [{id:55,…}, …]
4 tool    数据洞察助手   get_annotation_overview  result {dataset_count:273, task_count:237, image_count:2227}
5 tool    数据洞察助手   ai_query             args {question:"SELECT COUNT(*)…"}
8 reply   数据洞察助手   数据集：273 个；摄像头：55 个
9 summary 全能分析助理   **当前系统数据：** 数据集 273 / 摄像头 55（在线 34、告警 7…）
```

前端呈现（块状，不写时间、不写「规划/工具/回话」字样）：

- **结构是分支树，不是聊天流**：`接活 → 各成员支线（工具 + 回话）→ 汇总`。
  因为真实的协同是星形（组长 ↔ 每个成员），成员之间不说话，所以不会出现两个 agent 交替发言。
- 每条支线的圆点 = 谁（名字哈希取色）；工具行点一下才展开返回（限高自己滚），
  行尾的小数字是返回里的关键值（如 `273`）。
- 汇总结尾块用橡木色左条，失败时变红。
- **同一份数据同时画在 3D 大屏上**（墙上大屏 = 这份 trace 的投屏版）。

### 5. 状态与统计（都是真数据）

| 能看到 | 来源 |
|---|---|
| 谁在忙 / 忙什么 / 空闲 | `ai_call_logs`（近 10 分钟）+ `ai_office_activity`（派单当场标记） |
| 今日简报（派活次数、参与人数、最忙的人、平均耗时） | `ai_call_logs`（`usage=team|agent`） |
| 调用日志 | `ai_call_logs` |
| 会话记录 | 每次派活自动建会话并落用户消息 + 结论（`ai_sessions`） |
| 回放 | `ai_run_steps` 历史 |

## 三、不能干什么（边界，说清楚免得误会）

1. **不是聊天窗口**：办公室没有连续多轮对话（每次派活是独立一轮，不继承上次上下文）。
   要连续聊去「AI 应用 / 工作台」。
2. **不做审批**：没有真正的 HITL 确认流；待确认只是徽标。
3. **不自动重试**：组长最多按指令重派一次，没有任务队列、没有失败重跑、没有取消按钮。
4. **3D 场景不是业务**：走动、开会、迟到、访客都是表现层，不改数据。
5. **不替你安排日程**：定时任务是独立模块（`/ai/cron`），办公室不承担。

## 四、典型用法

| 你想干的事 | 怎么说 / 怎么做 |
|---|---|
| 摸家底 | 「让数据洞察助手报一下数据集、标注任务、模型各有多少」 |
| 定性分析 | 派给「数据查询助手」（绑了知识库），问口径/定义类问题 |
| 写材料 | 派给「文档编写助手」（绑了 4 个技能），让它出 Markdown |
| 查外部信息 | 派给「企业协作助理」（绑 web_fetch + 2 个 MCP） |
| 只看一个人 | 选中他 → 单独派给他（快，省掉组长一层） |
| 看它到底干了什么 | 右侧「执行过程」逐块看；看墙上大屏 |

## 五、怎么验证（自己试的时候照这个顺序）

1. 选中「数据洞察助手」→ 单独派：「报一下数据集和标注任务各有多少」→
   右侧应出现 `get_annotation_overview` / `list_datasets` 等**真工具块**，带真实数字。
2. 顶栏「派活」·「让数据洞察助手统计数据集数量，再让企业协作助理整理成一句话」→
   应看到 `delegate_task_to_member` 两块 + 成员工具块 + 组长汇总。
3. 刷新页面再点同一个人 → 步骤还在（落库了，不是前端内存）。

## 六、已知短板（下一步优先级）

| 优先级 | 短板 | 影响 |
|---|---|---|
| 低 | 任务列表没有全文搜索（只能按天 + 成员 + 状态筛） | 想找回「上个月那句原话」还得逐个点 |
| 中 | 组员取数仍会先拉 `list_*`（已把上限压到 50 行、并在指令里要求优先 `ai_query` / `get_*_overview`） | 一轮仍可能要 60–90 秒 |
| 中 | 上下文只保留最近 3 轮、且只记「问 + 结论」（中途工具细节不进记忆） | 特别长的追问链会丢早期细节 |
| 中 | 大屏一次只显示 4 块（长任务会截断） | 只看到片段 |
| 低 | 3D 里没有「任务卡片」悬浮（只能看大屏/面板） | 表现层小遗憾 |
