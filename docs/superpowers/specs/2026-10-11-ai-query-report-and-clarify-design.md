# 自定义报表生成 + 多轮反问 + 人类反馈 —— 设计

> 背景：ds:4 的 NL2SQL 已做到 **单表/指标 100%、多维 88%、排名 83%、窗口函数 53%**。
> 困难题的首次成功率靠调 prompt 已到天花板（补示例、错题自动沉淀均经留出法验证**无效**）。
> 结论：**困难题与自定义报表要靠"分层降级 + 人机协同"**，而不是让模型一次猜对。
>
> 本文只覆盖三条主线：**报表模板沉淀 / 多轮澄清反问 / 人类反馈**。
> （两段式分解生成、结果自校验列为后续迭代。）

## 1. 核心转变

| 旧目标（做不到） | 新目标（工程可交付） |
|---|---|
| 任何自定义报表**一次生成就对** | **同一类需求第二次一定对**（模板沉淀） |
| 模型猜用户想要什么 | **不确定就问**（多轮反问） |
| 自动从评测题学（已验证无效） | **人类确认/修正后沉淀**（反馈） |

## 2. 数据模型

### 2.1 报表模板 `ai_query_reports`

| 列 | 类型 | 说明 |
|----|------|------|
| `id` / `uuid` / `status` / `is_deleted` / 时间戳 | 标准 | 与项目其它表一致 |
| `key` | varchar(64) | 唯一标识（英文） |
| `name` / `description` | varchar/text | 中文报表名 / 说明 |
| `datasource` | varchar(32) | `system` 或 `ds:{id}` |
| `question` | text | **原始自然语言需求**（沉淀时的那句话） |
| `params` | jsonb | `[{key,label,type,default}]`，`type ∈ value/date_range/enum` |
| `sql_template` | text | 参数化 SQL（占位符复用现有 `_render_template`） |
| `columns` | jsonb | 输出列定义 `[{name,label,type}]`（表头/导出用） |
| `chart` | jsonb | 图表建议 `{type,x,y,series}`（可空） |
| `verified` | bool | **是否经人工确认**（false = 草稿，不进快路径） |
| `enabled` / `sort` | 标准 | 运营开关 |

**与 `ai_query_metrics` 的关系**（关键，避免重复造轮子）：

| | 指标 metrics | 报表 reports |
|---|---|---|
| 输出 | **单个数值**（1 行 1 列） | **多行多列**（分组/排名/窗口） |
| 典型 | 今日告警数 | 各煤种月度化验汇总表 |
| 复用 | 同一套 `sql_template` + `params` + `_render_template` + `validate_sql` + 标识符加引号 | 同上，多 `columns`/`chart` |

→ **实现上共用执行链路**，只是报表多"列定义 + 图表 + 导出"，且**不进快路径自动匹配**（报表由用户显式选择或反问后选择）。

### 2.2 澄清轮次（复用现有会话）

**不新增表**：澄清问答继续写 `ai_query_messages`，在 `grounding` JSON 里加
`{"clarify": {"field": ..., "options": [...], "answered": ...}}`。

### 2.3 人类反馈（字段已存在，只需真正用起来）

`ai_query_messages.feedback`（up/down）+ `correct_sql` 已有；新增 `report_id`（若该次问答最终沉淀成报表）。
**4534 条消息 0 条反馈** —— 前端链路从未接通，这是首要修复项。

## 3. 多轮澄清反问（重点）

### 3.1 何时反问（**确定性检测**，不靠模型）

在**检索/匹配阶段**就能拿到信号，命中任一即反问：

| 信号 | 检测方式 | 反问示例 |
|------|----------|----------|
| **分组键歧义** | 问句提到实体 E，本体里 E 同时有"名称列"和"编号列" | 「按**原煤仓名称**还是**原煤仓编号**分组？」 |
| **联表歧义** | 问句提到的实体可通过多条关系边到达（>1 条路径） | 「设备名从**组态设备表**取还是**人脸设备表**取？」 |
| **口径歧义** | 同时命中 ≥2 个指标，且分数接近（差值 < 阈值） | 「你要**今日**告警数还是**本月**告警数？」 |
| **时间缺失** | 问句含"平均/占比"但无时间范围，而候选表数据跨度 > 1 年 | 「统计**最近30天**还是**全部**？」 |
| **列太多** | 命中表 > 6 张 | 「可以只看这几张表吗？」（列出） |

**实现落点**：`AiQueryService.ask()` 在**快路径匹配之后、生成 SQL 之前**插入
`_detect_clarify(question, datasource, metrics, terms, recall) -> dict | None`；
命中则**不生成 SQL**，直接返回 `{path: "clarify", clarify: {...}}`。

### 3.2 反问的数据契约

```json
{
  "path": "clarify",
  "clarify": {
    "field": "group_key",
    "question": "按「原煤仓名称」还是「原煤仓编号」分组？",
    "options": [
      {"label": "原煤仓名称（BUNKERNAME）", "value": "BUNKERNAME"},
      {"label": "原煤仓编号（BUNKERID）",   "value": "BUNKERID"}
    ],
    "allow_free_text": true
  }
}
```

前端渲染成 `el-radio-group` + 输入框；用户选择后，**把选择拼回问句**再调 `/ask`：

```
原始问句 + "\n【澄清】按原煤仓名称(BUNKERNAME)分组"
```

→ **复用现有链路，无需新接口**。（`session_id` 保持不变，形成多轮。）

### 3.3 限制（避免骚扰）

- **每轮最多反问 1 次**（`grounding.clarify_count`），再问就直接生成；
- 用户可选"**不再问，直接查**"（记入会话偏好）；
- 反问**必须在 1 秒内**返回（纯规则判定，不调 LLM）。

## 4. 人类反馈闭环

### 4.1 三条反馈路径

| 路径 | 用户动作 | 系统动作 |
|------|----------|----------|
| **纠错** | 点踩 + 填正确 SQL | 存 `feedback='down'` + `correct_sql`；**提示"存成报表模板？"** |
| **确认** | 点踩后选"我要的是这个"（澄清） | 记录 `grounding.clarify.answered`，供下次同类问句**优先**该选项 |
| **沉淀** | 在结果页点「存为报表」 | 以 `verified=false` 建 `ai_query_reports` 草稿，等确认 |

### 4.2 与"自动沉淀"的区别（重要）

- 自动从**评测题**沉淀 → **已验证无效**（留出法 −4.76）且必然泄漏，**不做**；
- 人类反馈沉淀 → 样本来自**真实需求**，且**经人工确认**（`verified=true`）才生效。

### 4.3 反馈如何影响后续问答（可验证）

1. `verified=true` 的报表进入**报表快路径**：同类问句（语义相似 ≥ 阈值）**直接推荐该报表**，用户一键执行；
2. 澄清选项的**历史选择**作为下次反问的**默认项**；
3. **效果必须用留出法验证**（A 半沉淀、B 半评测），不能只看同一批题。

## 5. 生成 → 确认 → 复用 流程

```
用户自然语言
   ↓
[澄清反问]（命中歧义时，1 轮）
   ↓
LLM 生成 SQL + 列定义 + 图表建议
   ↓
执行 + 结果自校验（占比合计/排名连续/行数合理）
   ↓
展示结果 + 「存为报表」按钮
   ↓
用户确认 → verified=true 落库（ai_query_reports）
   ↓
下次同类问句 → 直接推荐该报表（带参数）
```

## 6. 接口（新增，尽量少）

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/ai/query/reports` | 报表列表（含 verified 过滤） |
| `POST` | `/ai/query/reports` | 新建/更新报表模板（upsert by key） |
| `DELETE` | `/ai/query/reports` | 删除（软删） |
| `POST` | `/ai/query/reports/{id}/run` | 带参数执行（复用指标执行链路） |
| `POST` | `/ai/query/reports/{id}/verify` | 人工确认（置 `verified=true`） |

`/ask` 的返回**新增 `clarify` 分支**（不改现有字段）。

## 7. 验收标准

1. **澄清反问**：对「每个设备下上限最高的两个测点」这类题，系统**先问**"按设备名称还是编号"，选择后能生成正确 SQL；**不反问时行为不变**（回归 0 失败）。
2. **报表沉淀**：一次成功问答能"存为报表"（草稿）→ 人工确认 → 在报表列表可见 → 带参数可重复执行，**结果与首次一致**。
3. **反馈落库**：点踩 + 正确 SQL 真正写进 `ai_query_messages`（当前 0 条 → 能查到）。
4. **效果可验证**：用**留出法**证明"报表快路径"对同类问句有提升（A 半沉淀、B 半评测）。
5. **不骚扰**：每轮最多反问 1 次；1 秒内返回。

## 8. 实施顺序（建议）

| # | 任务 | 价值 | 依赖 |
|---|------|------|------|
| 1 | **人类反馈链路接通**（点踩 + 正确 SQL 落库） | 最高（当前 0 条） | 无 |
| 2 | **澄清反问**（确定性检测 + `/ask` 新分支 + 前端选择框） | 高（治"猜需求"根因） | 无 |
| 3 | **报表模板**（表 + CRUD + 执行 + "存为报表"） | 高（把困难题变成一次沉淀长期复用） | 1 |
| 4 | 结果自校验（占比/排名/行数） | 中 | 3 |
| 5 | 两段式分解生成 | 中（治窗口函数首次成功率） | 2 |

## 9. 风险与诚实边界

- **澄清会打断体验** → 必须"最多 1 次 + 可跳过 + 1 秒内"；
- **报表模板会过期**（表结构/口径变了）→ 执行失败时提示"模板需更新"，并允许就地编辑；
- **不要承诺"任何自定义报表一次就对"**：首次 ~55%（困难题），**靠沉淀把重复需求做到接近 100%**；
- **任何"改进"都必须留出法验证**（本项目的血泪教训：近义题泄漏曾让 +14 个点全是假的）。

## 10. 已 A/B 验证的方案与结论（**动手前先看这里，别重复踩坑**）

| 方案 | 验证方式 | 结果 | 处置 |
|------|----------|------|------|
| **错题自动沉淀 few-shot**（从评测题） | 留出法：A 半沉淀 → B 半评测 | **−4.76**（76.19% → 71.43%）；且**近义题泄漏**会让同批评测虚高 +14 个点 | ❌ **回滚**，不再用评测题反哺 |
| **两段式分解生成**（先出计划再写 SQL） | 留出法：同一批 B 半 53 题，唯一变量 `two_stage_planning`；纯生成（剔除指标快路径） | ❌ **−7.55 点**（83.02% → 75.47%）；**错误率 0% → 9.43%**（5 题整题失败）；窗口函数 −8.34、排名TopN −16.66；**仍无窗口函数改善** | ❌ **默认关**（`two_stage_planning=false`）；代码保留可随时试 |
| 结果自校验（占比/累计/排名/分组行数） | 单测 6 条 + 真机跑通 | 已上线（可疑带具体错因重试一次，不阻断） | ✅ 保留 |
| 澄清反问（确定性歧义检测） | 单测 5 条 + 真机 DOM 核对 | 已上线 | ✅ 保留 |
| 人类反馈链路（修正 SQL 落库 + 沉淀） | 端到端真库验证（feedback/correct_sql/沉淀） | 已上线（修掉 2 个 bug：uuid/status 缺失致事务回滚、系统白名单误拒 ds:4） | ✅ 保留 |
| 报表模板（沉淀/确认/复用） | 真库 CRUD + 执行验证；**"复用增益"尚未 A/B** | 已上线（后端+前端+菜单） | ⚠️ 增益待真实使用后验证 |

**两条最重要的纪律（两次 A/B 都用上了）**：
1. **先定判定规则，再看数字**（"持平或更低 → 回滚/默认关"），否则容易事后找理由；
2. **必须同题留出对照**：近义题泄漏是"自我改进"最隐蔽的坑——完全相同能防，**近义改写防不住**。

**为什么两段式没治好窗口函数**：窗口函数的失败**不在计划层**
（计划里 `ROW_NUMBER() OVER (PARTITION BY ...)` 写得对），而在**执行结果的列/取值**
——所以计划再对也救不了。这条诊断把"窗口函数剩下 41%~53% 失败"的性质定死了：
**不是"想不清楚"，是"投影/取值"**。
