# AI 对话 V2 · Vercel AI SDK 迁移实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把前端 AI 聊天从手写 SSE 解析迁移到 Vercel AI SDK（`useChat` + 自定义 `AgnoChatTransport`），并重做消息呈现层，实现流式打字机、思维过程、Agent 工具调用时间线、富文本、输入现代化与会话管理。

**Architecture:** 后端保持 Agno 原生 SSE 零改动；前端新增 `AgnoChatTransport implements ChatTransport` 把 Agno 事件映射为 `UIMessageChunk` 流，交给 `@ai-sdk/vue` 的 `useChat` 托管消息状态与 parts 组装；UI 层按 `UIMessage.parts`（text/reasoning/tool/source/data）渲染。

**Tech Stack:** Vue 3.5 + TS、Vite 6、`ai ^7` + `@ai-sdk/vue ^4`、`markdown-it`/`highlight.js`/`dompurify`、`vue-json-pretty`、`@codemirror/*`、Element Plus、vitest。

**Spec:** `docs/superpowers/specs/2026-10-16-ai-chat-v2-design.md`

## Global Constraints

- 前端仅用 Element Plus 组件与 `--el-*` 变量；编辑器/构造器用成熟第三方组件；**禁止自造主题化外壳**。
- 注释/文案中文；提交信息中文（如 `feat(ai-chat): ...`）。
- 完成后**无头浏览器截图 + 多模态读图**核对与既有页面（如 `module_system/param`）风格一致。
- `pnpm run type-check`、`pnpm run lint`（仅改动文件）、`pnpm test:unit`（`src/**/*.test.ts`，`environment:"node"`，纯逻辑测试）均需通过。
- 不新增依赖（`ai`/`@ai-sdk/vue`/`markdown-it`/`highlight.js`/`dompurify`/`vue-json-pretty`/`@codemirror/*` 均在依赖中）；mermaid/katex 不在本计划内。
- 后端零改动。

## Review Focus

1. Agno 流中 `tool_call_id` 缺失或被截断 → transport 须按 `toolName+序号` 生成稳定 id，保证 `tool-input-available` 与 `tool-output-available` 成对。
2. 流中混入非 JSON 行 / 解析失败帧 → transport 跳过该帧，不中断整个流。
3. `text-start` 后直接 `error`（无 `text-end`）→ `useChat` 仍能捕获错误并正确置状态。
4. 会话切换 / `regenerate` 时旧流不污染当前会话（abortSignal 贯通）。
5. 长文本 / 长工具 JSON 渲染不卡顿，聊天区自动滚动到底。

- [ ] **Step 1: 写失败测试（`mapAgnoEvent` 纯函数）**

```ts
import { describe, it, expect } from "vitest";
import { mapAgnoEvent } from "../agnoChatTransport";

const ctx = { messageId: "m1", seq: 0, textStarted: false, reasoningStarted: false };
it("RunContent → text-start + text-delta + text-end", () => {
  const out = mapAgnoEvent("RunContent", { content: "Hi" }, ctx);
  expect(out.map(c => c.type)).toEqual(["text-start", "text-delta", "text-end"]);
  expect(out[1]).toMatchObject({ type: "text-delta", delta: "Hi" });
});
it("ReasoningContentDelta → reasoning-start + reasoning-delta + reasoning-end", () => {
  const out = mapAgnoEvent("ReasoningContentDelta", { reasoning_content: "分析" }, ctx);
  expect(out.map(c => c.type)).toEqual(["reasoning-start", "reasoning-delta", "reasoning-end"]);
});
it("ToolCallStarted → tool-input-available（生成 id 防缺失）", () => {
  const out = mapAgnoEvent("ToolCallStarted", { tool: { tool_name: "ai_query", tool_args: { q: "x" } } }, ctx);
  expect(out[0]).toMatchObject({ type: "tool-input-available", toolName: "ai_query", input: { q: "x" } });
  expect(out[0].toolCallId).toBeTruthy();
});
it("ToolCallCompleted → tool-output-available（与 input 同 id）", () => {
  const started = mapAgnoEvent("ToolCallStarted", { tool: { tool_name: "ai_query", tool_args: {} } }, ctx);
  const tid = started[0].toolCallId;
  const out = mapAgnoEvent("ToolCallCompleted", { tool: { tool_name: "ai_query", tool_call_id: tid, result: { rows: 1 } } }, ctx);
  expect(out[0]).toMatchObject({ type: "tool-output-available", toolCallId: tid, output: { rows: 1 } });
});
it("RunError → error chunk", () => {
  expect(mapAgnoEvent("RunError", { error: "boom" }, ctx)[0]).toMatchObject({ type: "error", errorText: "boom" });
});
it("RunStarted / RunCompleted → step 边界", () => {
  expect(mapAgnoEvent("RunStarted", {}, ctx)).toEqual([{ type: "start-step" }]);
  expect(mapAgnoEvent("RunCompleted", {}, ctx)).toEqual([{ type: "finish-step" }]);
});
it("未知事件类型返回空（跳过不中断）", () => {
  expect(mapAgnoEvent("FooEvent", {}, ctx)).toEqual([]);
});
it("content 非字符串跳过 text（解析失败容错）", () => {
  expect(mapAgnoEvent("RunContent", { content: 123 }, ctx)).toEqual([]);
});
```

- [ ] **Step 2: 运行测试确认失败**

Run: `pnpm test:unit -- agnoChatTransport`
Expected: FAIL（`mapAgnoEvent` 未定义）。

- [ ] **Step 3: 实现 `mapAgnoEvent` 与 `AgnoChatTransport`**

在 `agnoChatTransport.ts`：
- `MappedCtx { messageId, seq, textStarted, reasoningStarted, toolIds: Map }`；为每个消息管理文本/推理 part 的 start/end 状态，并用 `toolIds` 缓存 `toolName→toolCallId` 保证 input/output 成对。
- `parseAgnoFrame(raw: string): { event: string; data: any } | null`：按 `event:`/`data:` 解析单个 SSE 块；`JSON.parse` 失败或无 data 行返回 `null`（调用方跳过）。
- `mapAgnoEvent` 按上表映射；`toolCallId` 用 `data.tool.tool_call_id || data.tool.toolCallId || "tool-" + toolName + "-" + (++seq)`；`content` 非字符串时返回 `[]`；未知事件返回 `[]`。
- `AgnoChatTransport.sendMessages({ messages, abortSignal, body })`：`fetch` `base + path`，POST `{ messages: messages.map(m => ({ role, parts: m.parts.filter(p=>p.type==="text").map(p=>({type:"text",text:p.text})) })), ...(body ?? {}) }`，带 `Authorization` 与 `X-Forwarded-For: 127.0.0.1`、AbortSignal；用 `ReadableStream` + `TextDecoder` 逐帧（`\n\n` 分隔）解析，`parseAgnoFrame` 返回 `null` 则跳过，否则调 `mapAgnoEvent` 并 `controller.enqueue`；`RunCompleted` 后 `controller.close()`。
- `buildBody?: () => Record<string, unknown>` 用于透传 `session_id`/`knowledge_ids`/`model_id`。
