# 全系统「配置化 + 易用性」评审规范（所有模块通用）

> 适用：AI 管理、视频、训练、标注、边缘、系统等**全部**模块。
> 目标：任何"新建/编辑"都不许是"一个参数干巴巴的表单"，要让配置**完整、可选、可视化、方便**。
> 每个模块上线前按本清单评审。

---

## 一、配置项完整性（不许简陋）
- 编辑/新建表单的字段应**覆盖业务所需全参数**，而非只留 1-2 个核心项。
- 每个配置项都应提供：**默认值**、**可选性**（不必填则允许留空/继承默认）、**范围约束**（min/max/步进）。
- 涉及"留空继承上级默认"的项（如模型温度、token、超时）用空值＝继承，并在占位符说明。
- 重要交互项（slider/开关/多选/标签/多级选择）优先用专门控件，而非裸输入框。

## 二、可视化构造器（禁止裸 JSON）
- 任何"入参/请求头/配置/Schema/变量"**不许**让用户手写 JSON/代码。
- 应提供：字段构造器（名/类型/默认/必填）、键值对构造器（名/值）、下拉/多选/开关 等可视化输入。
- 提交时自动序列化；编辑时反向解析回可视化结构。
- 例外：调试者技术输入（如单节点调试变量、SQL）可保留原始文本，但提供"示例填充"按钮。

## 三、交互反馈（用户感知）
- 操作后**明确反馈**：成功/失败 toast，成功文案与按钮动作一致。
- 会耗时的操作给**加载态/进度**；长任务给周期进度（局部刷新，勿整表闪）。
- **删除/清空/覆盖**类必须二次确认，写明影响范围与数量。

## 四、页面友好度（清新化）
- 空态用 `el-empty` + 引导文案（邀请行动，不是干巴巴"暂无"）。
- 列表/卡片有**搜索、筛选、分页**；大型列表支持批量操作。
- 标题/字段名用**用户语言**（"通知设置"而非"webhook config"），动词明确（"保存更改"）。
- 关键信息支持**详情抽屉/预览**，不只是列表。

## 五、出场标准（每模块评审通过才交付）
| 项 | 达标 |
|----|------|
| 配置项 | ≥3 个以上业务参数，有默认/范围/说明 |
| 无裸 JSON | 入参/请求头/配置均为可视化构造器 |
| 交互反馈 | 成功/失败/加载/二次确认齐全 |
| 列表 | 搜索/筛选/分页/空态齐全 |
| 音量 | 类型含义、默认值、筛选项覆盖 |

> 评审工具：检查单 + 无头浏览器截图核对；后端 ruff / 前端 type-check / lint 通过。

## 六、推进策略（长期分批）
1. 按**用户感知频率**排序：高频（训练任务、视频布控、标注）> 中频（AI 管理已达标）> 低频（系统设置）。
2. 每批做 1-2 个模块：**评审 → 补配置项 → 可视化改造 → 交互反馈 → 验证提交**。
3. 复用已建立的**字段/键值对构造器、二次确认、局部刷新**等通用模式，保证全系统观感一致。
