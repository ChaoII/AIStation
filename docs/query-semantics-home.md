# 问数语义的「家」：哪些能配、哪些还写死在代码里

> 原则见 `AGENTS.md`「工程原则：语义/口径不写死在代码里」。
> 一句话判定：**改一条业务口径如果需要发版，它就放错了位置。**

## 三、明确留在代码里的（不是缺陷）

- **安全护栏**：`dialect.CORE_RULES`（只读 SELECT / 必须 FROM / 只用给定表）、
  `sqlguard.FORBIDDEN_RE`（禁 DDL/DML）、白名单校验、fail-closed 逻辑。
- **协议/错误处理**：重试、降级、超时、SSE 帧格式。
- **上表各项的默认值**：必须存在，且必须能被库里的配置覆盖（有单测）。

## 三点五、界面可维护性（2026-11-12 追加要求）

治理闭环（发现 → 处置 → 配置）现在都在界面里：

- **发现**：治理 →「问答体检」（`GET /metrics/audit`）：扫该数据源**全部题库**（可按数据集过滤），列出①可疑指标②抢答（定义收紧：命中指标、快路径准入不拦，但金标 SQL 查的表不是该指标绑定的表）③**悬空引用**（指标/实体映射/本体对象/术语指向的表在资产目录与当前数据源 schema 里都找不到）；
- **处置**：清单里直接「停用」（只关开关，不改口径），或「去改名」到指标页；
- **配置**：「语言规则」页含 14 组词表 + 6 个开关 + **指标护栏参数**（兄弟限定词/最小长度）；
- **语义数据**：术语/指标/资产别名/本体别名/关系/权限都在各自页面维护；
- **分区原则**（2026-11-13 归位）：**维护语义**在「数据与集成」（数据源/表与字段/指标/术语/关系图），**评估与监管**在「治理」（驾驶舱/权限/质量/血缘/策略 + **问答体检/治理包**）。原先放在问数设置里的两块已搬过去，问数页只留跳转按钮（`/ai/governance?tab=query-audit|bundle`）。
- **批量与迁移**：治理 →「治理包」把 830 张表的别名/描述、本体对象别名、术语打成 JSON：
  导出可下载，导入先「预演」看差异（新增/更新/重复行/未知表）再「应用」，只更新包里有值的字段；
  这也把「换环境要重录」变成一次导入。

仍属「初始化脚本」而非日常治理：`seed_holdout_set.py`（造留出题）、`seed_ontology_aliases.py`（给对象补一批初始别名）、`rebind_ontology_ds.py`（换数据源时搬对象）。

用户原话：「我目前 UI 做了很多功能，这些你调试的点都需要在 ui 里面能够维护和体现」。

- 数据源编辑页新增两段：**软删口径**（列名 + 词表）、**时间口径**（周起始日 + 月份口径）。
- 接口返回**生效值**（默认值合并后），不是库里原始 JSON —— 看见的必须等于生效的。
- 两处 `normalizeRules`（数据源弹窗 / 筛选规则工作台）改为**保留未识别键**：旧实现会在保存时把后端新增字段静默丢掉。
- 数据源编辑弹窗内容区 `max-height:66vh` 自适应滚动，底部字段不再被裁掉。
- 问数设置新增「**配置地图**」：11 项「要改什么 / 在哪改 / 什么时候用」+ 跳转。

## 四、迁移模板（每迁一项照做）

1. 先把**默认值**从代码挪到一个函数（如 `softdelete_rules(None)`），保证行为不变；
2. 从正确的表/配置读覆盖（旧 JSON 不要求重存：逐键合并）；
3. 加单测：`默认生效` + `覆盖生效` + `坏配置回落默认`；
4. 跑 `pytest -k "query"` + `query_golden_smoke.py`；
5. 跑 105 题回归（准确率、快路径占比不降）后再提交。
