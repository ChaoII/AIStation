## 2. 还原（本地新库，不动 aistation）

```bash
docker exec -e PGPASSWORD=ServBay.dev aistation-pg-rag \
  psql -h 127.0.0.1 -U root -d postgres -c "CREATE DATABASE ezdcs_yuanmei OWNER root"
docker exec -e PGPASSWORD=ServBay.dev aistation-pg-rag \
  pg_restore -h 127.0.0.1 -U root -d ezdcs_yuanmei -j 1 --no-owner --no-privileges \
```

## 8. 新模块专项测评（19 题）

105 题主要覆盖老表（批次/化验/流水），对新补的合同、采样制样、计划覆盖不足，
因此另做一组 19 题专项测评（gold 在 ds:6 上现算，统一排除软删）：

- **19 / 19 = 100%**
- 覆盖：合同份数/合同总吨数/合同平均单价、质量约束、模板条款、采样/制样单与明细、
  元素碳含量、硫分、热值、工业分析灰分、年度/月度计划进煤量、月计划明细、日计划、
  组态画面、人员、小程序版本。
- 过程中修掉的 4 个指标路由问题：
  1. `is_rowcount_metric` 补 `*_count` 后缀 → 「合同总数量是多少吨」不再回 40 份；
  2. 多术语命中时按**更长/更具体**的术语改判 → 「硫分化验」不再被短术语「硫分」拉回煤质表；
  3. 新增合同质量约束/采样明细/月计划明细/化验碳含量 4 个指标；
  4. 指标 SQL 里 `EXTRACT(... FROM CURRENT_DATE)` 会被 SQL 白名单误判成表名
     （「表 CURRENT_DATE 不在白名单」）→ 改为从数据里取最新年度/月份。



## 9. 数据量评估（够不够）

| 维度 | 现状 | 评价 |
|------|------|------|
| 合同 | 40 份 × 12 个月数量、50 条质量约束、300 条模板条款 | 功能演示够用；做供应商/月度对比偏少 |
| 采样制样 | 采样 933（演示 240）、制样 3091（演示 240）、明细 243/720 | 覆盖 2025-10 ~ 2026-11，月均约 17 条演示采样，趋势分析偏薄 |
| 细项化验 | 元素/硫/热值/工业分析/水分各 **2527**（覆盖全部化验单） | 够用 |
| 计划 | 年 1+12、月 12+60、日 30+60、采购 12+60 | 够用（5 个供应商/月） |
| 组态/人脸/小程序 | 画面 12、组件 40、引用 120、人员 20、版本 6 | 功能演示够用；分页/大批量场景偏少 |

**已知局限（不是外键错误）：**

1. **批次→合同只能连上 3 份合同**：源库 232 条有效批次只有 **4 个供应商名称**，
   而合同覆盖 30 个供应商，交集只有 3 个。这是源数据供应商维度稀疏导致的；
   要做「按合同统计批次/按供应商对比」，需要再补批次数据（增加供应商/矿点维度）。
2. 合同月度数量是**均分**（余数落 12 月），没有季节性。
3. 新补的化验数值是**合理区间随机值**，不是由现有化验结果推算。
4. 源库里 4 条批次日期为 `1900-01-01`，采样关联时已排除，但未改源数据。
