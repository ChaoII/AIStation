> 回答「都到位了吗」：**功能到位，口径已对齐，准确率没到位**。下文全部是实测数字与复现方式。

已知缺陷（按影响排序）：

1. **表消歧弱**：留出集 6~7 条错在选错表（`ASSAY` vs `ASSAYCHECKSUGGESTION`、`PLANDAY` vs `STG_DAYCOALINFO`）。

2. **指标命名混乱**：69 个绑定指标里存在「配煤方案结果明细表STOQTY合计」这类拼装名，容易被别的问句抢。

4. 4 条留出题出题/金标不严谨（已记录在 `docs/holdout-v1.md`）。

### 本次修掉的「口径不一致」

本体对象 `datasource_id` 一直绑在 **ds:4（远端）**，而问数默认数据源已切到 **ds:6（本地副本）**，
于是同一个业务对象两套数字：

| 对象 | ds:4（修前） | ds:6（修后） |
|------|-------------|-------------|
| 入厂煤批次 | 287 | **577** |
| 燃煤合同 | 0 | **120** |
| 采购结算主表 | 4 | **36** |

修复：`scripts/rebind_ontology_ds.py`（先 `--dry-run` 再 `--apply`），把 336 个对象迁到 ds:6，
全部按 `backing_table` 校验目标库存在；迁后实例聚合与业务库**逐项相等**。

### 消歧为什么不生效（已修）

排查发现**两个叠加 bug**，导致本体这条最强信号形同虚设：

1. `object_table_map()` 同时返回 `ont_x -> x` 和 `x -> x`，而 `recall_ontology` 用
   `setdefault` 建 code→table 映射，先遇到的 `ont_x` 被固化 → 通道返回 `ont_xxx`，
   **和 schema 表名对不上，整条通道的分数在融合时被丢弃**；
2. `ai_ont_object.aliases` 全是空数组，别名档本身没有词。

修复与验证（2026-11-12）：

- 优先取不带 `ont_` 前缀的表名；档内按**命中词长度降序**（更具体的别名优先，
  避免「期初库存」压过「期初库存明细」）；
- `scripts/seed_ontology_aliases.py` 给 46 个易混对象补业务别名
  （期初库存/盘点/配煤分仓/成本项目/化验审核…），幂等、可 `--dry-run`；
- 留出集 v2 的**召回命中率：29/37 → 37/37**（修复前 8 条正确表根本没进候选）。

### 对象查询路径为什么关掉

实测 8 种问法（「煤质信息」「入厂煤批次有多少条」「按煤种统计…」等）**没有一条走 `path=object`**：
路由前置条件（时间/分组/排序/聚合/列举/条件）会全部跳过它，剩下的场景又先被指标快路径接走。
即使带 `object_code` 上下文提问也是 fast/slow。结论：这条路径目前不产生任何收益，
`object_query_enabled` 置 **false**（省一次无用的尝试）；要重启只需把它改回 true 并单独评测。

> 本体对问数的实际贡献路径是**绑定型指标**（69 个指标走本体实例层），不是对象路径。

### 指标护栏（二版，已上线）

一版护栏回退的原因是**别名为空**（拦谁谁错）。别名补齐后同规则重跑，并修掉两个实现问题：

- 绑定型指标的 SQL 是 `SELECT 1`（没有 FROM），护栏取不到表名 → 回落到 `object_code`；
- 资产表名带 `ont_` 前缀（影子表）→ 别名表同时按去前缀键登记，且剔除「别名=表名」的垃圾值；
- 别名含括号说明（`煤场进煤记录(流水)`）→ 同时存一份去括号版本。

效果：

| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| holdout-v2 | 59.46% | **89.19%**（33/37，fixed 11 / regressed 0） |
| 105 题 | 99.05% / fast 31.43% | **99.05% / fast 31.43%**（完全不变） |
| v2 快路径占比 | 21.62% | 8.11%（拦掉的劫持改走慢路径，属预期代价） |

### 跨表抢答（三版，已上线）

计数型护栏管不到 `sum/avg`：「期初库存明细的 QTY 合计」被库存指标抢、「配煤结果的混煤量」
被 `..._stoqty` 抢。补一条**通用的竞争别名规则**：问句点到了**别的表**的业务别名（长度 ≥4
且与本表别名不互相包含）时，该指标不参战。

- v2：89.19% → **97.30%（36/37）**，只剩一条「取前 3 个单据号」——那是**我方金标过严**
  （题面没写并列规则），不是产品问题；
- 105：**99.05% / fast 31.43%，完全不变**；
- 中间踩过一次：这条规则把「供应商矿点关系」的指标挡了（该表别名写的是「供应商矿点对应」，
  问句说「关系」）→ 105 掉到 98.1%。补别名后恢复。**规则和别名必须一起演进**。
