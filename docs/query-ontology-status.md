### 本次修掉的「口径不一致」

本体对象 `datasource_id` 一直绑在 **ds:4（远端）**，而问数默认数据源已切到 **ds:6（本地副本）**，
于是同一个业务对象两套数字：

| 对象 | ds:4（修前） | ds:6（修后） |
|------|-------------|-------------|
| 入厂煤批次 | 287 | **577** |
| 燃煤合同 | 0 | **120** |
| 采购结算主表 | 4 | **36** |

修复：`scripts/rebind_ontology_ds.py`（先 `--dry-run` 再 `--apply`），把 336 个对象迁到 ds:6，
全部按 `backing_table` 校验目标库存在；迁后实例聚合与业务库**逐项相等**。

### 消歧为什么不生效（已修）

排查发现**两个叠加 bug**，导致本体这条最强信号形同虚设：

1. `object_table_map()` 同时返回 `ont_x -> x` 和 `x -> x`，而 `recall_ontology` 用
   `setdefault` 建 code→table 映射，先遇到的 `ont_x` 被固化 → 通道返回 `ont_xxx`，
   **和 schema 表名对不上，整条通道的分数在融合时被丢弃**；
2. `ai_ont_object.aliases` 全是空数组，别名档本身没有词。

修复与验证（2026-11-12）：

- 优先取不带 `ont_` 前缀的表名；档内按**命中词长度降序**（更具体的别名优先，
  避免「期初库存」压过「期初库存明细」）；
- `scripts/seed_ontology_aliases.py` 给 46 个易混对象补业务别名
  （期初库存/盘点/配煤分仓/成本项目/化验审核…），幂等、可 `--dry-run`；
- 留出集 v2 的**召回命中率：29/37 → 37/37**（修复前 8 条正确表根本没进候选）。

### 对象查询路径为什么关掉

实测 8 种问法（「煤质信息」「入厂煤批次有多少条」「按煤种统计…」等）**没有一条走 `path=object`**：
路由前置条件（时间/分组/排序/聚合/列举/条件）会全部跳过它，剩下的场景又先被指标快路径接走。
即使带 `object_code` 上下文提问也是 fast/slow。结论：这条路径目前不产生任何收益，
`object_query_enabled` 置 **false**（省一次无用的尝试）；要重启只需把它改回 true 并单独评测。

> 本体对问数的实际贡献路径是**绑定型指标**（69 个指标走本体实例层），不是对象路径。
