# 数据资产 → 数据与集成：合并与元数据人工维护

**这篇记录第 2、3 步改造：把散落的「数据资产」并进「数据与集成」，
并让人工维护元数据（中文名/描述/关联关系）真正可用。**

## 一、改造前的问题（用户原话：「很散乱」）

| 模块 | 实际是什么 |
|---|---|
| **数据与集成** `/ai/integration` | **只读摘要**：连接表 + 管道表 + 一个导入小组件。点「新建连接」「新建管道」**只弹一句提示**"请在智能问数→指标运营里管理"——真正的 CRUD 在别处 |
| **数据资产** `/ai/asset` | 5 个只读标签（数据资产/指标/术语/概念/图谱），**一个字都改不了** |

**两个页面都是只读的**，而「维护表/字段的中文名、描述、关联关系」这件事
**根本没有入口**。用户说的"我看你很多功能都是有的啊"，指的正是这个。

## 二、关键发现：**能力和接口早就有了，缺的只是界面**

排查后发现后端与前端 API **全部齐备**：

| 已有能力 | 位置 |
|---|---|
| 表级元数据保存（中文名/业务域/描述/业务场景/是否对象化/主键列/显示名列） | `POST /ai/query/assets/save` |
| **字段级元数据保存**（中文描述 + **关联表/关联字段**） | `POST /ai/query/assets/column/save` |
| 字段元数据模型 | `ai_query_asset_columns`（含 `related_table`/`related_field`） |
| 字段清单 | `GET /ai/query/assets/{table}/columns` |
| 自动推断字段关联 | `POST /ai/query/assets/infer-relations` |
| 自定义图谱关系 | `POST /ai/query/assets/kg/relation` |

前端也已封装 `saveQueryAsset` / `saveQueryAssetColumn` / `getQueryAssetColumns`。

> **所以我没有重复造后端接口**（一度加了 `save_asset_meta`/`save_column_meta`，
> 发现与既有 `upsert_asset` 重复后**全部删除**）。这一轮的工作量**在界面**。

## 三、改成了什么

`/ai/integration` 重写为**「选数据源 → 选表 → 就地维护」**一条路：

```
┌──────────────┬────────────────────────────────────────────────────┐
│ 数据源        │ [表与字段] [管道] [指标] [术语] [概念] [血缘]        │
│ ───────────  │ ┌────────────┬───────────────────────────────────┐ │
│ ● 燃煤业务库  │ │ 表清单(搜索)│ CMMS_CANVASCOMPONENT  [保存表信息] │ │
│   MES接口API  │ │ CMMS_...   │ 中文名[__] 业务域[__]              │ │
│   ERP生产库   │ │  组态画面…  │ 业务描述[____________]            │ │
│   MES生产库   │ │ AI_PIC...  │ 业务场景[__] 纳入问数[●]           │ │
│              │ │ CMCS_...   │ 业务对象[○] 主键列[__] 显示名[__]  │ │
│ [+新建]       │ │            ├───────────────────────────────────┤ │
│ 测试 / 编辑   │ │            │ 字段(5) 中文名|关联表|关联字段|保存│ │
│              │ │            │ ID      [__]  [____]  [____]  [保存]│ │
└──────────────┴────────────────────────────────────────────────────┘
```

- **表清单显示上游中文注释**（如「组态画面所引用的组件」），搜索可按中文名过滤
- **字段的「中文名」自动预填上游注释**，省一次手输；人工值优先
- **关联表 / 关联字段**就是「人工维护表之间的关系」——上游库没外键时靠它
- 「导入为本体对象」按钮就地可用

**旧菜单与路由已清理干净：**
- 菜单 363「数据资产」已软删
- `src/views/module_ai/asset/` 整个目录已删除（无任何引用）
- 前端路由加了一条 **`/ai/asset` → `/ai/integration` 重定向**，老链接不会 404

**顺带修好：菜单 358「智能问数」原本是隐藏的**（`hidden=true`），用户根本看不到它，已取消隐藏。

## 四、顺带挖出并修掉的两个性能炸弹

做这一步时页面报 10 秒超时，查下去发现**两个接口慢到离谱**：

| 接口 | 修前 | 修后 | 原因 |
|---|---|---|---|
| `GET /assets/list` | **31.5 秒** | **2.57 秒** | **N+1 查询**：567 条资产 × 3 次查询 ≈ 1700 次，且 `_asset_dq_score`/`_asset_lineage_count` **每次都新开一个数据库会话**（又占一条池连接） |
| `GET /assets/kg/stats` | **23.2 秒** | **2.18 秒** | 同上量级 |

改成 3 次聚合查询（`GROUP BY`）一次拿全，并在同一个会话内完成。

**这两个接口就是「页面到处报错」的直接元凶**——它们把连接池拖满，
其它接口跟着一起超时。修完后全页面巡检：

| 页面 | 修前控制台错误 | 修后 |
|---|---|---|
| 模型管理 | 12 条 | **0** |
| 应用 | 11 条 | **0** |
| 调用日志 | 9 条 | **0** |
| **全部 12 个页面** | 共 16 条超时 | **0 条超时** |

## 六、还没做的（诚实说明）

1. **表级「删除/清空」类操作没有二次确认**——目前这页**没有删除功能**，
   所以不涉及；后续若加删除必须补 `ElMessageBox.confirm`。
2. **字段表在窄屏下仍需横向滚动**（列多）。已把「类型/上游注释」并进字段单元格、
   左侧表清单压到 240px，1280 宽下基本够用，更窄的屏需要滚动。
3. **「新建管道」仍然只弹提示**——管道的编排界面还在「智能问数 → 指标运营」里，
   **这一步没合并**（工作量大，且用户这次没点名要它）。
4. **没有批量维护**——137 张缺注释的表要一张张填。批量导入（CSV/Excel）**没做**。
5. **概念/指标/术语三个标签仍是只读**（它们的编辑在别处），只做了搬家，没做就地编辑。
6. **`/assets/list` 还有 2.5 秒**——已从 31.5 秒降下来，但对 567 条资产仍偏慢，
   进一步优化需要分页或去掉 DQ/血缘字段。
