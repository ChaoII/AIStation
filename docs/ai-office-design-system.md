## 0. 这一页不走 Element Plus 外观（2026-10-24 用户决定）

办公室是**唯一豁免框架 UI 规范**的页面：页面上已经有 Three.js 三维场景，再套
`el-card` / `el-tabs` / `el-table` 的观感会割裂。用户明确要求「所有元素做成精致的、不必遵守
Element Plus 与框架约束」。

因此本页自带一套皮肤 `of-*`（前缀避免与框架样式打架）：

| token | 值 | 用在哪 |
|---|---|---|
| `--of-paper` | `#fcfbf8` | 面板底（暖纸） |
| `--of-paper2` | `#f6f3ec` | 输入框、次级底、流水条 |
| `--of-line` / `--of-line2` | `#e6e0d4` / `#efeade` | 边框 / 分隔线 |
| `--of-ink` / `--of-ink2` / `--of-ink3` | `#2e2a24` / `#6f685d` / `#9a9285` | 主文字 / 次文字 / 弱文字 |
| `--of-oak` / `--of-oak-soft` | `#b07d3f` / `#f3e8d6` | 强调（取自场景里的橡木家具） |
| `--of-busy` / `--of-wait` / `--of-err` | `#3f7f6b` / `#c08a33` / `#b4543f` | 工作中 / 等你确认 / 失败 |
| `--of-mono` | `ui-monospace…` | 时间、计数、工具名、页码 |

落地约定：

1. **页面里已经没有任何 Element Plus 组件**（顶栏、页签、日期步进、状态胶囊、成员下拉、
   页码条、成员行、任务行、执行过程全部自绘）；`ElMessage` 提示条除外。
2. 顶栏 `.of-bar`：原生 `<input class="of-input">` + `.of-btn`（主按钮橡木 `#b07d3f`）
   + `.of-seg`（1F/2F 分段）+ 两个 `.of-ico`（↺ 最近一轮 / ⟳ 刷新）；
   「改形象」浮层 `.of-pop` 挂在 `.of-look`（`position: relative`）下、**向左展开**，
   不压住右侧的执行过程；用一个全屏 `.of-pop-mask` 接外部点击关闭。
3. 成员行：头像 24px 圆形 + **迷你状态环**（`.m-av::after`）：忙碌青绿呼吸（1.6s）、
   失败砖红、等待琥珀、待命透明。
4. 任务列表：**竖向时间轴**（`.of-tl`）——左列等宽时间、中间圆点（状态色）挂在一条
   `#e3dccd` 竖线上、右侧两行（问句 + `N 步 · 组长`）。
5. 3D 画布底色 `#f4f1ea`，与面板接缝不出现冷灰；页面底 `#efece5`，面板 `#fcfbf8`。

## 1. 设计原则

1. **场景优先**：办公室本身是主角。信息尽量放进 3D 场景里（墙上的大屏、人身上的工牌），
   **不要用 modal / 抽屉**去盖住它。
2. **零浮层**：本页当前没有任何 `el-dialog` / `el-drawer`。页面外壳只有两条控制条
   （顶部工具栏、左侧花名册）。
3. **昼夜同源**：场景、大屏、工牌、所有覆盖物共用同一套昼夜配色，夜里不能出现"白底卡片"。
4. **一个强调色**：白天蓝 `#2f7fd6`，夜里青 `#5ec8ff`；琥珀 `#e6a23c` 只用于"等你确认/加班"。
5. **读数用等宽**：所有数字（统计、耗时、计数）用 `ui-monospace, "JetBrains Mono", Consolas`。

## 3. 场景约定

### 3.1 房间与坐标

- 房间：`FW = 13.5`（x）、`FD = 9.5`（z）、墙高 `WH = 1.78`；地板 `y = 0`。
- 相机：正交，`VIEW = 12.5`，默认 `zoom = 1`，方位角约 45°（等距视角），
  `minZoom 0.8 / maxZoom 2.4`，禁平移。
- 导航：A* 网格 `CELL = 0.15`，原点 `(-6.9, -4.9)`，`92 × 96` 格
  （往 +z 多留 31 格给露台）。
- **露台**：`z ∈ [4.8, 8.4]`、`x ∈ [-4.3, 4.3]`，木地板 + 玻璃栏杆 + 三把遮阳伞
  + 三张高脚桌（6 凳）+ 2 个靠栏杆站位 + 夜里一串暖光灯。工具栏「看露台」切换视角
  （`zoom 0.72`，target 取房间与露台之间）。

### 3.2 座位（`SEAT_DEF`）

| key | 类型 | 用途 |
|---|---|---|
| `dA`~`dD` | desk | 工位 |
| `front` | front | 前台（组长固定） |
| `qc` / `qc2` | room | 会客室两把椅子 |
| `coffee1/2` | coffee | 咖啡吧（带杯子道具） |
| `sofa1/2` | sofa | 沙发（带手机道具） |
| `gym` | gym | 跑步机 |
| `st0..n` | stand | 站立位（含墙边扩容位） |
| `terrace00..22` | terrace | 露台高脚凳 |
| `terrace_rail1/2` | terrace | 露台靠栏杆站位 |

座位粘性：轮询刷新时老人留在原座位；**刚被演出挪过的人 4 秒内不跟轮询走**
（`rec.movedAt` 守卫，防止"走一半被拽回去"）。

### 3.2.0 楼层偏移的坑（务必看）

`mesh()` 会给**所有**物体加 `buildingY`。因此：

- 用 `new THREE.Group()` 自己摆位置的组（显示器 `mon`、椅子 `chair`、玻璃 `glassRun`），
  **组本身不要再加 `buildingY`** —— 组里的子件已经被加过了，再加就是双层偏移（显示器飘到半空）。
- 用 `new THREE.Mesh` + `scene.add` 直接挂到场景的对象（大屏、楼梯立牌、工牌），
  必须**自己补 `buildingY`**。

### 3.2.0.1 家具构件的两条硬规则

1. **工位显示器**：`mon` 组自己带 `+ buildingY`，**子件用 `new THREE.Mesh` 直接建**
   （不能走 `mesh()`，否则又被加一次 `buildingY`，屏幕会飘到桌子外面）。
   支架同理，底座和立柱要落在桌面上（`y ≈ 0.775 / 0.9`）。
2. **椅子**：坐垫 0.1 厚 + 靠背微后仰 + 腰托 + **两侧扶手（托面 + 立杆）**
   + 气杆 + 五星脚 + 5 个滚轮。四件套缺一件就会显得"廉价塑料"。

### 3.2.0.2 家具细节自查清单（每次改场景必看）

放大到单件家具逐个看，以下每一条都踩过坑：

1. **桌腿 vs 抽屉柜**：柜子占着右下角，那根腿要省掉，否则穿模。
2. **绿植**：`plant()` 的组已经带 `buildingY`，组内子件要临时把 `buildingY` 归零，
   否则花盆飘到半空；叶子用扁椭圆（0.085×0.23×0.022），别用锥体（像刺）。
3. **圆桌椅子朝向**：`chair()` 默认面朝 -z；桌子南侧的椅子要 `ry = PI`，北侧 `ry = 0`，
   座位表里的 `ry` 必须和椅子一致。
4. **沙发坐垫**：底座宽 1.9 → 两个坐垫各 0.84、中心 ±0.46，别超出底座。
5. **立牌**：用 `THREE.Sprite`（永远朝镜头）；`PlaneGeometry` 在斜视角下会被背面剔除，
   即使设了 `DoubleSide` 也可能看不见。
6. **楼梯口**：立牌杆立在台阶**右侧空地**，不要插在踏步上，也别贴墙。
7. **CanvasTexture**：`draw()` 之后必须 `tex.needsUpdate = true`，否则贴图是空白。
8. **座高要和坐姿匹配**（骨盆底 = `hip - 0.095`，要正好落在座面上）：
   工位椅面 0.52 → `work.hip 0.615`；沙发垫面 0.495 → `sitback.hip 0.59`；
   吧台凳 0.64 → `coffee.hip 0.735`。改座高时三处要一起改，否则屁股会陷进去或浮起来。
9. **凳子**：4 条外撇腿 + 脚圈（`stool()`），不要用"一根细杆 + 圆盘"，看着像蘑菇。
10. **顶栏**：白底卡片 + 细边框；蓝灰只做页面背景，不承载内容。
11. **工牌要 `depthTest: false` + `renderOrder 20`**，否则会被绿植/家具挡住（3D 里的浮层
    不能靠"离得近"来保证可见）。
12. **同一张 canvas 别给两个物体用**：楼梯牌两层共用一个 canvas 时，后画的会覆盖前一层
   （一层牌子显示成"1F ↓"）。每层各自建 canvas + texture。

### 3.2.1 材质与反射

- 环境反射：`RoomEnvironment` 经 `PMREMGenerator` 烘一张，`scene.environmentIntensity = 0.12`
  —— **只给金属/玻璃加 `envMapIntensity = 1.7`**，哑光面几乎不受影响（调高会整屋发白）。
- 银色金属：低金属度 + 低粗糙度（`metal` m .22 / r .26），靠主光打紧的高光；
  高 metalness 在没有环境反射时只会变灰，不要调。
- **显示器是一个 group**：边框、屏幕、底座都在同一坐标系里，屏幕内凹 2mm。
  早期版本把屏幕和边框各自 `rx: -0.26` 摆放，差 7mm，看起来像"画面飘在显示器外面"；
  另外桌上那条 `screenGlow` 光条原本钉在桌子中心（x 而非 mx），也是"脱离"的来源，已删。

### 3.3 墙上的大屏（简报 / 结论）

- 位置：`(-3.4, 0.98, -FD/2 + 0.1)`，尺寸 `2.4 × 1.35`，夹在白板与窗户之间。
- 贴图：`1024 × 576` 的 canvas，`setScreen(mode, data)` 绘制，`mode ∈ {idle, brief, result}`。
- 打开时镜头推进：`zoom 4.2`，`target` 移到大屏；点场景任意处或 `closeScreen()` 退回。
- 内容排版：顶部 `BRIEF/RESULT` 等宽标签 + 四角 L 形标记 + 6 格统计（brief）或
  正文 30px/6 行（result）。

### 3.3.1 玻璃房轮廓光

- 顶部沿口 + 地脚各一圈 12mm 细条，材质 `glassEdge`（`#cfe9ff` + 青色自发光）。
- 白天 `emissiveIntensity = 0.18`（几乎看不见），夜里 `1.5`（勾出会客室轮廓）。
- 目的：夜里房间整体压暗后，玻璃房仍然一眼认得出是"能开会的地方"。

### 3.4 3D 工牌（代替右侧抽屉）

- 触发：点人（花名册或场景名牌）→ 拉取详情 → `showBadge(data)`。
- 尺寸 `1.72 × 1.16`，canvas `512 × 344`，始终 `quaternion.copy(camera.quaternion)`（正面朝镜头）。
- 位置：头顶 + 相机右向 0.92 + 上向 0.34；**起点是胸口**（头顶 − 上向 0.44）。
- 动画：420ms，`1-(1-p)³` 缓出；缩放 `0.14 → 1`，透明度 `0 → 1`（前 190ms 淡入更快）；
  收起时原路缩回并隐藏。引线在前 190ms 淡入到 0.55。
- 打开时镜头轻微推近（`zoom 2.05`，target 在人身上）。

### 3.3.2 二层（夹层）

- **布局与一层不同**：一层是 4 张散落工位 + 会客室 + 咖啡吧；二层是「项目区」——
  两排 6 个工位（`F2_DESKS`）+ 北墙 4 人窗边长桌（`F2_BENCH`，对着窗办公、配笔记本）
  + 圆会议桌（2 把椅子）+ **茶水角**（台面 + 咖啡机 + 2 个高脚位）
  + **左墙书架**（带彩色书脊）+ **沙发角**（地毯 + 双人沙发 + 圆茶几）
  + **打印机 + 边柜** + **挂钟** + **白板** + **两幅挂画** + 3 处绿植 + 楼梯口
  + **休息室（寝室）**：地毯 + 两张躺椅（带靠背/枕头）+ 边几。
  二层共 16 个座位。

  > 绿植是程序化的 `plant(x, z, scale, tone)`：陶盆 + 土 + 主干 + 6 片长叶（锥体），
  > 不再是"一个绿色球"。一层露台的两处也换成了它。
- 建造方式：`buildingFloor = 2; buildingY = FLOOR_H(3.55);` 之后照常调 `desk()` / `chair()`，
  `mesh()` 会自动把物体抬高并打 `userData.floor` 标。
- **寻路分两层**：`makeNav(obstacles)` 工厂 → `NAV`（一层障碍表）与 `NAV2`（二层障碍表）。
  `navFor(floor)` 按楼层取网格，`moveTo / walkTo / 卡住重算` 都走它。
  二层的座位要 `NAV2.carve()` 挖口，否则座位落在桌子障碍里会被判非法丢掉。
- **楼梯口**：每层都有一个小台阶 + 发光立牌（`2F ↑` / `1F ↓`），**点它上下楼**
  （点击命中判定用投影坐标，半径 52px）；工具栏的 1F/2F 按钮是同一功能的备选入口。
- 切换：`setFloor(1|2)` 遍历场景，把不属于当前层的 **Mesh/Line/Sprite** 关掉
  （Group 不动，否则会连带关掉子节点），`hiddenByFloor` 记住原始可见性。
  灯光、相机永不隐藏。
- 人物零件在创建时由 `addAgent` 统一打上座位所属楼层（`makePerson` 内部临时清空
  `buildingFloor`，避免零件被拆散）。
- 脚点投影要带 `p.y`（二层的人脚点不能按 y=0 投影，否则全飘到楼下）。

### 3.4.1 人物造型

- **已知名字**（`LOOK` 表）用手写配色；**未知名字**按名字哈希从调色板取一套
  （12 色衬衫 × 6 色裤子 × 7 色头发 × 5 种发型 × 3 种布纹），同一人永远同一套。
  —— 这是几十个智能体不变成"一片灰"的关键。
- 细节：衬衫领（两片小三角）、腰带（比裤子深一档）、鞋底（浅一档）、胸牌、眉眼、
  两种嘴型（笑/说话）。
- **LOD**：`lite = 人数 ≥ 10` 时省略领子、眉毛、胸牌，减少三角面。

### 3.4.2 形象编辑（用户可改）

- 选中某人 → 工具栏「改形象」→ 弹层里改：**发型**（短发/侧分/锅盖/丸子头/长发）、
  **衬衫 8 色 / 裤子 6 色 / 鞋子 6 色 / 头发 6 色**，点一下**当场生效**。
- 实现：`setLook(name, patch)` 只替换材质引用（按旧材质 identity 换新材质），**不重建模型**，
  几十个人也是瞬时。
- 持久化：`localStorage["office:looks"] = { [agentId]: {shirt, pants, ...} }`，
  打开页面时 `restoreLooks()` 逐个刷回去。

### 3.4.3 工具调用时间线（落库）

- 新表 `ai_tool_calls`（插件自建，`logs_center/tool_calls.py`）：
  `agent_id / agent_name / tool_name / args / duration_ms / ok / created_time`。
- 写入时机：`office_dispatch_stream` 里每完成一次工具调用写一行；Team 委派不会发
  tool 事件，所以 **`runstarted`（成员被点名）也记一条 `delegate_task_to_member`**。
- 接口：`GET /ai/logs/tool-calls?agent_id=&limit=`。
- 大屏 `WORK LOG` 优先用工具记录（工具名 / 耗时 / 成败），没有工具记录时退回
  `ai_call_logs` 的调用记录。
- ⚠️ **写库必须 `async_db_session.begin()`**：`async_db_session()` 只给会话不提交，
  之前 `office_activity` 的标记其实一直没落库（本轮回填修复）。

### 3.4.4 执行过程时间线（对话式）

- 新表 `ai_run_steps`（`logs_center/run_steps.py`）：一次派活 = 一个 `run_id`，
  按 `seq` 记录 `plan`（规划）/ `tool`（工具）/ `reply`（成员回话）/ `summary`（汇总）。
- 写入点：`office_dispatch_stream` 的 start / 委派 / 成员回话 / 收尾。
- 接口：`GET /ai/agents/office/steps?agent_id=&run_id=&limit=`；
  给 `agent_id` 时先找"他最近参与的 run"，返回**整条 run** 的步骤（这样能看到组员回话）。
- 前端：舞台右上「执行过程」面板（336px，白底、细边框），**块状**呈现，不写时间、不写类型文字：
  - 每一步一个色块（左侧 3px 色条 + 6% 同色底）：规划蓝 / 工具紫 / 汇总橙 / 失败红；
  - 块头左上角：`执行人` +（工具步）`· 工具名` + `→ 目标成员`（工具名等宽紫色）；
  - 块体：任务/正文，3 行截断，点块展开；
  - **成员回话折叠进对应工具块**，作为缩进"结果"块（按成员名匹配，不依赖相邻）；
  - 派活过程中随 SSE 帧实时追加。

### 3.4.5 工牌上的工作日志

- 选中某人时，**墙上大屏同时切到 `WORK LOG`**：显示他的状态、分类，以及最近 6 条执行记录
  （当前任务 + 最近调用）。大屏只换内容、**不动镜头**（`setScreen(..., { focus: false })`），
  镜头仍然对着人；取消选中时大屏回到 `idle`。
- 工牌本身也带两行日志（见下）。

- 工牌下半部分显示两行：**「正在做：<当前任务>」**（来自 `office_view.task`，实时）
  + **一条最近调用**（`/ai/logs/recent` 里属于该 agent 的，带时间/类型/成功失败）。
- 这样"谁在干什么、干过什么"不用跳出场景就能看到。

### 3.5 气泡（对话）

| 类型 | 样式 | 停留 |
|---|---|---|

### 执行过程是「分支树」，不是聊天流

真实的协同是**星形**：组长接活 → 拆给若干成员 → 各自干活 → 回报 → 组长统一口径。
成员之间不通信，所以界面上**不应该**出现两个 agent 交替说话的观感。

渲染规则（`.of-trace`）：

```
◉ 接活 · 组长
│   用户原话
│
├─ ● 问数助手            1 次工具
│    get_annotation_overview  （无参数）      273
│    └ 回话：系统现有 273 个数据集
│
├─ ● 数据洞察助手        2 次工具
│    list_cameras  limit=50                  55 条
│
└─ 汇总 · 组长
    数据集 273 个、摄像头 55 个…
```

- 顶层节点 = `kind=plan` 的步骤；每条支线 = 一次 `delegate_task_to_member`（按目标成员）；
  支线内挂该成员的工具调用与回话；底部 = `summary` / `error`。
- **工具行点一下才展开返回**，返回限高 76px 自己滚；工具后面的小数字是返回里的关键值
  （如 `273`），空格子不再摆一屏 JSON。
- 颜色还是两通道：支线圆点 = 谁（名字哈希），汇总块左条 = 橡木（失败时红）。

## 7. 已知取舍

1. 大屏在北墙，视角 45°，文字有透视压缩 —— 换来"真的在场景里"而不是贴一张平面图。
2. 名牌在人多时会自动收敛（≤12 全显，>22 只显忙/等），避免糊成一片。
3. 休息区上限 `n-2`：全去摸鱼看起来假，所以强制留人在工位。
4. 会客室只有 2 把椅子，第 3 个人站着开会 —— 不再加家具，保持房间比例。
5. 场景没有真实环境光遮蔽的接触阴影，靠自写 SSAO + 贴地柔影近似。
6. **容量**：当前座位表 **50 个**（1F 26 + 露台 8 + 2F 16），`CAP = min(52, 座位数)`；
   超出的人不渲染，页面头部显示「N 位未入座」。要真正上几十人，见下面「扩容路线」。

## 8. 扩容路线（几十个智能体怎么办）

按成本从低到高：

1. **站位/工位扩容（0.5 天）**：加椅子、把站位沿墙排开；当前已到 26，继续加会开始"挤"，
   因为房间只有 13.5 × 9.5 米。
2. **分区办公（1-2 天）**：同一层划三个区（研发区/运营区/会客区），每个区独立座位表 +
   独立导航网格，镜头按"当前关注的人"在区之间平移。**推荐先做这个**。
3. **露台（已完成）**：前侧开敞区做成了户外露台（木地板 + 遮阳伞 + 高脚桌 + 灯串），
   新增 8 个座位，`ROWS` 扩到 96。下一步是**第二层**（`floor` 状态 + 两套场景组，
   镜头按楼层上下平移）。
4. **LOD + 实例化（1 天）**：>30 人时人物换成低模（现在是 ~2000 三角面/人），
   远处用 InstancedMesh 或直接简化成"色块小人"，近处再换回精细模型。

## 9. 人物"更逼真"的取舍

现在的人物是**程序化卡通**（每人大约 2000 三角面，靠代码拼出来，没有骨骼动画文件）。
好处：几十个人零成本、颜色/发型随便变、包体不增加。

想更逼真有三条路：

| 方案 | 效果 | 成本 | 风险 |
|---|---|---|---|
| 继续打磨程序化（加衣服层次、手部、坐姿细节） | 卡通感更精致 | 1-2 天 | 无 |
| glTF 骨骼模型（Mixamo/ReadyPlayerMe 那类） | 接近游戏角色 | 3-5 天 + 每个模型 3-10MB | 40 个 skinned mesh 很吃性能，需要 LOD/实例化 |
| 2D 序列帧 / Sprite | 手绘动画质感 | 2-3 天 + 美术资源 | 与 3D 场景透视难对齐 |

结论：**要"几十人 + 好看"，程序化是正解**；只有确定人数在 10 人以内、且愿意接受包体变大，
才值得换 glTF。
