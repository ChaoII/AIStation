# AI 智能体 / 工作流编排：关系与分类体系

> 目的：明确「智能体」与「工作流编排」的**关系**，并给出一套可落地的**分类方式**，
> 用于 AI 管理平台的菜单/导航、文档与产品规划。

---

## 一、智能体 vs 工作流：并列关系，且互相组合（可嵌套）

**结论：不是"包含关系"，而是"并列关系 + 互为组件（可嵌套调用）"。**

| 维度 | 智能体 Agent | 工作流 Workflow |
|------|-------------|----------------|
| **决策主体** | 大模型自主决策 | 人为预先编排 |
| **执行路径** | 不确定（LLM 边想边走） | 确定（DAG 固定步骤） |
| **可复现性** | 不可控、结果波动 | 可控、可复现、可调试 |
| **适合场景** | 开放问题、动态任务 | 固定流程、批量/定时、合规审计 |
| **调用关系** | 会**调用工具/技能/工作流** | 会把**智能体当作节点**放入 |

**一句话**：工作流是**"手脚"**（确定执行），智能体是**"大脑"**（自主决策）。
二者**并列**，但**互为组件**——智能体能编排工作流，工作流内也能挂智能体节点。
这也是 Coze / Dify / LangGraph 的通用做法。

### 为什么"新建"会让你选
因为**聊天 / 智能体 / 工作流 / 知识库问答** 是**并列的可创建对象**，
各自独立，但可以互相引用组合。这是别人产品里"新建时能选不同类型"的原因。

## 二、推荐分类方式（两层）

### 第一层：按「应用形态」分（前端新建入口 / 一级分类）

| 应用类型 | 说明 | 对应 AIStation 模块 |
|---------|------|--------------------|
| 🗨️ 聊天机器人 (Chat Bot) | 纯对话，无 / 浅工具 | `module_ai/chat` |
| 🤖 智能体 (Agent) | 有记忆、会调工具/技能、自主决策 | `module_ai/agent`（含分类、技能安装） |
| 🔀 工作流 (Workflow) | 可视化 DAG 编排、版本/定时/HITL | `module_ai/workflow` |
| 📚 知识库问答 (KB QA) | 检索增强、可溯源（RAG+图谱+引用） | `module_ai/knowledge` |
| 🧩 支撑件 | 会话 / 技能 / 工具 / Prompt 模板 | `sessions / skill / tools_catalog / prompts` |

### 第二层：按「编排引擎」分（底层能力 / 二级视角）

| 类型 | 说明 |
|------|------|
| 确定性工作流 | 预定义 DAG，步骤固定，可版本化/定时/审计 |
| 自主智能体 | LLM 循环（Agent loop），调用工具/记忆迭代 |
| 混合编排 | Agent 内嵌 Workflow、Workflow 挂 Agent（彼此嵌套） |

---

## 三、落地的建议

- **一级菜单**：按「应用形态」分（聊天 / 智能体 / 工作流 / 知识库 / 支撑件）。
- **二级**：在「智能体」「工作流」内部，再按「编排引擎」区分编排模式（确定性 / 自主 / 混合）。
- **新建入口**：让用户选「聊天 / 智能体 / 工作流 / 知识库问答」，符合并列关系。
- 文档与导航统一采用本分类术语，避免"智能体 vs 工作流谁包含谁"的歧义。
